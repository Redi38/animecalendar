# Аниме-календарь

Календарь выхода аниме на русском языке, в духе livechart.me.

- **Афиша.** Зима / Весна / Лето / Осень любого года (1980 — текущий + 2). Тайтлы сгруппированы по дням премьеры, есть сортировка по популярности, фильтр по формату (ТВ, фильмы, ONA/OVA) и фильтр по названию внутри сезона. Для текущего сезона страница сама прокручивается к ближайшему дню. Рядом с сезонами есть вкладка «Без даты»: анонсы, у которых студия ещё не назвала ни сезон, ни дату выхода (самые популярные из них, список обновляется раз в 6 часов).
- **Поиск.** По русскому, английскому названию и ромадзи; учитывает падежи («луна» найдёт «Луну») и «ё». Подсказки при наборе в шапке, Enter открывает полную выдачу.
- **Просмотренное.** Кнопка с глазом на любой карточке. Список хранится в браузере, его можно скачать файлом и загрузить на другом устройстве. Кроме скачанного файла можно загрузить JSON со списком названий (`[{"title": "..."}]` или массив строк): сайт найдёт каждое через поиск и добавит. Это занимает около секунды на тайтл.
- **Мои анонсы.** По просмотренному сайт идёт по графу связей (продолжения, предыстории, спин-оффы, побочные истории, альтернативные версии) и показывает то, что ещё не вышло или выходит сейчас: «Продолжение · из «…»». Ищет цепочкой до трёх шагов, поэтому анонс третьего сезона найдётся, даже если второй вы не отмечали. Новые анонсы подсвечиваются значком «Новое» и счётчиком на вкладке. Тайтлы из вашего списка отмечаются и в сезонной сетке («★ Связано с вашим списком»).
- **Карточка тайтла.** Русское описание, студия, жанры, дата следующей серии, связанные тайтлы, ссылки на Shikimori, AniList и MyAnimeList.

## Откуда данные

| Что | Источник |
| --- | --- |
| Сезоны, даты, форматы, обложки, связи между тайтлами | [AniList](https://anilist.co) (GraphQL) |
| Русские названия, русские описания, поиск кириллицей | [Shikimori](https://shikimori.io) |

Тайтлы связываются по MAL ID (`idMal` в AniList = ID на Shikimori). Всё, что пришло, сохраняется в локальный SQLite-кэш: свежие сезоны обновляются раз в несколько часов, старые раз в две недели, при сбое внешнего API сайт отдаёт то, что есть в кэше. Если Shikimori недоступен, показываются оригинальные названия.

Сезон на сайте — это сезон премьеры, как его определяет AniList. Сериалы, которые начались раньше и ещё идут (long-runners), в сезонной сетке не дублируются.

## Запуск

```bash
make venv
cp .env.example .env
make run            # http://localhost:8000
```

Без интернета, на вымышленных тайтлах:

```bash
make demo
```

Docker:

```bash
cp .env.example .env
make up             # http://localhost:8020, кэш в ./data
```

Прогрев при старте (`PREWARM=true`) загружает текущий и следующий сезон, чтобы первый посетитель не ждал. Первый запрос к «холодному» сезону занимает несколько секунд (AniList отдаёт по 50 тайтлов за запрос), остальные берутся из кэша.

## Настройки (`.env`)

См. [.env.example](.env.example). Главное: `DB_PATH`, `SHIKIMORI_ENABLED`, `TRUST_PROXY_HEADERS` (включите за Caddy/nginx, иначе ограничение частоты запросов будет считать всех одним клиентом), `DEMO_MODE`.

## Разработка

```bash
make ci             # ruff, mypy, проверка JS, тесты
```

Тесты идут на вымышленных данных из `app/demo.py` и не обращаются к сети. Фронтенд — обычные ES-модули без сборки (`app/web/static/js`), данные внешних API вставляются в DOM только как текст, а не как HTML.

```
app/
  providers/   клиенты AniList и Shikimori (лимиты, повторы, мягкие ошибки)
  services/    catalog.py (кэш, сезоны, поиск, связи), related.py (обход графа), dto.py
  db.py        SQLite через aiosqlite
  web/         FastAPI-маршруты и статика
  demo.py      вымышленный каталог для демо и тестов
tests/
```

## Ограничения

- Список просмотренного — не более 500 тайтлов (предел одного запроса к API).
- Нет аккаунтов: список живёт в браузере. Перенос между устройствами — через файл.
- Расписание серий (`Серия N — через …`) берётся из AniList и есть только у идущих тайтлов.
- Внешние API с хостинга-песочницы, где писался проект, были недоступны, поэтому связка с живыми AniList и Shikimori проверена по их документации и на фикстурах, но не вживую. Перед выкладкой стоит один раз запустить `make run` на машине с интернетом и открыть текущий сезон.
